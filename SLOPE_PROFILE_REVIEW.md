## Main conclusion

The trigonometry is correct: slope angle is atan(vertical change / horizontal distance), with longitudinal positive meaning shoaling along increasing KP, and cross slope positive meaning deeper to starboard. The reliability problems are chiefly the sampling surface, physical measurement scale, coverage handling, and different definitions of cross slope. Both exaggerated slopes and missed steep features are possible.

## Findings, in priority order

1. **Depth Profile still defaults to raw interval slopes.** `depth_profile_dockwidget.py:268` defaults the slope window to zero; `_compute_slopes` at line 1704 then uses interval differences. Raster sampling at line 1318 uses provider point samples without explicit bilinear interpolation. Fine station spacing across cell boundaries can create steep spikes. A synthetic 10 m staircase with a 1 m depth increment, sampled every metre, gives a 45° maximum through the actual shared interval function; the underlying planar gradient is 5.7106°. Increasing point density can therefore make this result worse.

2. **KP Mouse's automatic window can collapse below the native support scale.** `maptools/kp_profile_math.py:profile_slope_series` clamps the window to each valid source run. This protects against crossing seams, but very short runs can still turn cell steps into extreme slopes. Reproduction: x=[0, 0.05, 0.1] m, depth=[100, 100, 101] m, pixel_size_m=10 gives 84.2894°, while reporting a nominal 10 m half-window. Such a line can straddle a cell boundary. Require enough supported baseline, and report the actual baseline or an insufficient-resolution result at truncated windows.

3. **Merging loses information needed by automatic slope scaling.** The merge uses the finest output resolution and nearest resampling by default (`processing/merge_mbes_rasters_algorithm.py`). Coarse pixels remain steps within a finer output grid; the quick-profile sampler sees the output pixel size, not the original local survey resolution. In the same 10 m staircase example, labelling the raster as 1 m cells causes the quick-profile function to return a 45° maximum. A merged raster also hides source boundaries from seam protection. Later-listed overlap priority can differ from the quick profile's resolution preference. Bilinear resampling can improve appearance but cannot restore provenance or correct datum offsets. The merge's own engineering note already acknowledges these limitations.

4. **Burial Planner bridges missing depths when calculating longitudinal slope.** `burial/profile_data.py:long_slope_series` calls the shared window function without missing-station masking or splitting into contiguous runs. That function removes missing depths and interpolates between remaining values. Reproduction: x=[0,10,20] m and depth=[100,None,120] m with half-window=10 m returns -45° at all three stations, including the missing one. Acquisition separately tracks no-data intervals, so this does not establish that every rule will falsely pass; nevertheless, displayed slopes and slopes near gap boundaries can incorporate unsupported terrain. The existing burial test explicitly expects interpolation across gaps despite its printed label mentioning gaps becoming None.

5. **Burial Planner does not preserve per-station source identity for slope evaluation.** `burial/analysis_task.py:DepthSnapshot` samples the configured raster order and returns depth values; persistent profile arrays do not attach source IDs. Longitudinal windows and port/starboard differences can consequently include different surveys and their vertical offsets. Its default longitudinal window follows profile spacing, rather than automatically respecting each contributing raster's native cell dimensions.

6. **Cross slope is not the same quantity across tools.** Depth Profile fits an ordinary least-squares line across 11 raster samples (21 for half-widths of at least 500 m), with a default half-width of 200 m. Burial Planner uses the difference between two offset depths divided by the full offset span. These are average tilt estimates with different spatial weighting. A symmetric depression can have zero endpoint tilt, and zero fitted overall tilt, despite steep walls. Neither should be labelled or interpreted as the maximum local cross slope. Depth Profile also drops missing samples, permits fitting from only one side, mixes raster sources, and predicts missing endpoint depths from the fit. It needs coverage/provenance checks and an explicit distinction between observed and predicted depths.

7. **Contour cross slope has additional assumptions.** Depth Profile intersects the transverse line, keeps only the nearest hit of each depth on each side, then fits a line; repeated crossings of a real ridge or depression can be removed by that deduplication. Both fit endpoints are extrapolated. Burial Planner instead interpolates along two offset route polylines and compares their depths. That can be useful, but is not the same reconstruction as transverse-contour fitting. Routes/offsets with few contour crossings need an explicit insufficient-information outcome. Contours do not resolve the seabed shape between equal-depth crossings.

8. **Depth Profile contour resampling can remove genuine detail.** `_sample_contour_mode` replaces exact crossings with a uniform series of 50–1000 stations when interpolation is enabled. Long routes can miss short features and slope breaks. Conflicting contour depths at the same station are not resolved before `np.interp`. Retain exact crossings alongside any display samples and flag conflicting observations rather than silently selecting a value.

9. **Seabed length does not share the slope coverage protections.** `_compute_seabed_length` removes missing depths before joining consecutive remaining points, and does not split on source changes. It can bridge data gaps, incorporate survey offsets, and accumulate raster stair-step noise. Horizontal distances between sampled points also shortcut intervening route bends. Report covered length separately and use route chainage differences within valid contiguous runs.

10. **Units and vertical conventions need explicit inputs.** KP Mouse uses projected pixel dimensions directly as metres and derives a scalar cell size from sqrt(pixel area); rectangular cells and projected CRSs in feet can therefore produce inappropriate windows. Depth Profile's projected cross offsets likewise assume map units are metres. Median-sign depth/elevation detection works for many offshore datasets, but is not a dependable vertical convention around zero; Burial Planner's absolute-value conversion also folds mixed-sign elevations. Use per-source horizontal/vertical units, positive-down/elevation convention, and datum metadata. Axis inversion should remain a display control.

## Recommended common calculation contract

- Preserve depth/elevation, source ID, native X/Y resolution, units, and validity at each station. Keep raw observations and interpolated results distinguishable.
- Define longitudinal evaluation length and cross evaluation width in metres independently of plot sampling density. Use the same selected method and scale in previews, exports, and burial rules. Do not silently enlarge a requested vehicle footprint beyond the supported survey resolution; flag the limitation.
- For MBES, add explicit, no-data-aware bilinear profile sampling and retain a raw-sample view. Validate slope windows against native resolution. Avoid interpolating across unknown coverage or unverified source seams.
- For contours, use exact line intersections and linear interpolation between valid bracketing crossings. Retain those crossings in analysis arrays. Expose contour-only mode for comparison with cable-lay software, but verify its settings and results before claiming equivalence.
- Distinguish overall cross tilt, local cross slope, and maximum absolute cross slope. If a fitted trend is offered, document its window, weighting, minimum coverage and fit residual. A local 2D gradient/plane fit is an option for raster terrain; it requires an explicitly shared support scale for longitudinal and transverse components.
- Keep display smoothing separate from analysis. Anti-aliasing and a restrained seabed fill can improve readability without modifying measurements. Avoid unconstrained splines that invent extrema, and never smooth across gaps.

Contours should not automatically replace MBES as the engineering default. They can give alignment with a particular delivery/workflow, but their apparently smoother result also reflects missing detail. A contour-only comparison preset is preferable to a silent global switch.

## KP quick-profile interaction

Current `maptools/kp_depth_profile_window.py` provides two linked plots, axis inversion, position persistence, and timer-coalesced live updates. `maptools/kp_mouse_maptool.py:keyPressEvent` provides D to toggle the window and Escape to clear the range origin. There is no dedicated freeze, measurement, or one-click PNG/CSV workflow; bundled plotting menus are not a substitute for a defined export contract.

Recommended interaction:

- Space toggles Live/Frozen, with a visible button and status. Freeze the map line, endpoints, displayed profile and pending refresh together.
- Two-click measurements on the frozen depth plot; optional snapping to a selected source curve; retain multiple annotations. Show horizontal width, signed/absolute depth change, endpoint distance and slope. Distinguish endpoint distance from distance traced along the seabed.
- Metres by default, with independent horizontal and vertical display/measurement units. Include undo/delete, clear all, cancel the unfinished measurement, and repeat.
- PNG exports the current plots and annotations. CSV exports chainage, depth/elevation, slope, source/validity and calculation metadata, plus a measurement table. Export a frozen snapshot.
- Shade below the seabed toward the deeper side, respecting axis orientation and gaps; a separate slope fill can shade positive/negative values to zero.
- Escape and Close dismiss cleanly, stopping pending updates. Offer click-on-map dismissal for an unpinned profile. Avoid unconditional focus-loss closure: entering an export dialog or unit selector must not close the profile or discard annotations. A pinned/frozen state should preserve work until explicit clear/close/resume.
