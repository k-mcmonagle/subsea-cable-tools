# Subsea Cable Tools

**Subsea Cable Tools** is a QGIS plugin for working with subsea telecom and power cable data: route position lists (RPLs), KP-based queries, bathymetry, lay corridors, and related survey/engineering tasks.

Targets QGIS 3.22 or newer and declares compatibility through QGIS 4.x (`qgisMaximumVersion=4.99`, Qt6 supported).

> **A note from the author.** Recent releases have added a substantial number of new tools, Processing algorithms and features, and several tools are still marked *beta*. Please treat the plugin as a **work in progress**. As always, **do not rely on the output uncritically — sanity-check and double-check results** against your own data and established methods before using them for any operational or engineering decision.
>
> — Kieran McMonagle

## Features

### Processing algorithms

Available in the Processing Toolbox under **Subsea Cable Tools**, in these groups:

- **RPL Tools** – Import RPL to Workbench (auto-detect) (the same detection, validation and registration as the Workbench's guided import), Import Excel RPL (legacy column-mapping import), Add RPL Layers to Workbench (register an RPL point/line pair already in the project; algorithm id `register_rpl`), Compare Design vs As-Laid Routes (radial, along-track and cross-track offsets), Translate KP Between RPLs (Points), Extract A/C Points from RPL, Identify RPL Crossing Points, Identify RPL Area Listing, Identify Features Intersecting RPL, Calculate Seabed Length.
- **KP Points** – Place KP(Z) Points Along Route (optionally with depth from a raster), Place KP Points from CSV, Place Single KP Point, Nearest KP, Add Depth to Point Layer.
- **KP Ranges** – KP Range Highlighter, KP Range Highlighter from CSV (a row whose start and end KP are equal is a position, written to the tool's second, point output rather than rejected), Merge KP Range Tables, Group Adjacent KP Ranges by Field, Extract KP Ranges (Rule Based), KP Range Depth + Slope Summary.
- **Cable Lay Data Import** – Create Cable Lay GeoPackage (sets up the empty standard layers), Import Cable Lay Data (CSV), Import Event Log, Import Slack Log, Import Body Log, Import 3D Model Solutions, Import As-Laid, Import Plough Data, and Recompute ISO Time (fix start date) to correct a wrong project start date without re-importing. Importers take several files at once, append to the chosen GeoPackage layer and drop duplicates.
- **Cable Lay QC & Analysis** – Run Cable Lay QC (time gaps, distance gaps, decimal precision, duplicates; writes a `qc_findings` layer).
- **MDB Tools** – Import MDB (GeoMedia `.mdb`/`.accdb` feature classes, including text labels; no Access driver needed), Import Path File (.pthmdb) (route, positions, segments, assembly points and bathymetry profile from a path database).
- **MBES Tools** – Create Raster from XYZ (direct, bin average or IDW gridding, multi-file), Merge MBES Rasters (keeps the finest input resolution).
- **Other Tools** – Dynamic Buffer (Lay Corridor), Export KP section chartlets, Extract Lines Intersecting Polygons, Import Ship Outline (DXF), Place Ship Outlines at Points, Place Outline Along Route (KP), Plot Line Segments from Table.

### Map & dockable tools

The tools below are in the **Plugins ▸ Subsea Cable Tools** menu, except the KP Mouse Tool, which is a toolbar button (its *Configure…* is also in the menu). KP Plot, Depth Profile, Catenary Calculator V2 and Transit Measure also have toolbar buttons; tools still in development share the toolbar's **Experimental** dropdown (Cable Route Workbench, Planner, Burial Planner, Cable Lay Data Explorer, Cable Lay Simulator, BU Lowering Tool).

- **KP Mouse Tool** – live KP/rKP/DCC under the cursor, a geodesic range ring, right-click depth sampling from several raster and contour layers, "Go to KP…", and a live depth/slope profile along the range line (press **D**; see [KP Mouse quick profile](#kp-mouse-quick-profile)). Configure it from the toolbar button's menu.
- **KP settings…** – how KP is measured across the whole plugin: **Geodesic** (WGS84, default) or **Cartesian** grid distances. See [Distance & CRS methodology](#distance--crs-methodology).
- **KP Plot** (KP Data Plotter) – dockable plot of KP-based table data against a route, with crosshair, marker and per-field axis assignment.
- **Depth Profile** – dockable profile from MBES raster(s) or contours along a route or temporary line; depth/slope plots with adaptive sampling, an optional *Nearest KP on route* X axis, on-plot two-point measurements (shared with the KP Mouse quick profile), vertical exaggeration and PNG/CSV export.
- **Transit Measure** – cumulative geodesic distance along a drawn path with transit-time output and an optional Quick Buffer.
- **Catenary Calculator V2** (multi-segment) — 2D static model with multi-span drape, chute wrap geometry and buoyancy analysis; see [catenary/MODEL_NOTES.md](catenary/MODEL_NOTES.md) for the precise assumptions and validity envelope. (The legacy V1 calculator was removed in 1.7.0.)
- **Save Layers to GeoPackage…** – also on the Layers panel right-click menu for vector layers. Saves the selected layers (including the layers inside selected groups) into one GeoPackage and points the project layers at the saved tables, keeping names, styles, group positions, joins and expression fields — like QGIS's *Make Permanent* for many layers at once. Saving into an existing GeoPackage asks before replacing tables of the same name; layers in edit mode are skipped and listed.
- **Cable Lay Simulator (3D)** *(beta)* — the next-generation catenary tool: interactive software-rendered 3D view plus profile/plan views over real bathymetry (including grids sampled from a project raster), with hydrodynamic drag throughout. Three modes: **Static hang** (V2 physics in 3D with current loading), **Steady lay** (ship speed + pay-out solved in the vessel frame, validated against Zajac 1957 closed forms which are shown live as quick answers), and **Operation simulation** (quasi-static stepping with a timeline scrubber: branching-unit deployment, final-bight lay-down, transient straight lay). CSV / 3D DXF export and results-to-map layers. Assumptions and validation status: [catenary/v3/V3_MODEL_NOTES.md](catenary/v3/V3_MODEL_NOTES.md).
- **BU Lowering Tool (3D)** *(beta)* — the simulator's branching-unit lowering scenario as its own focused dialog: position and laid ends set up on the map, bathymetry, the BU make-up measured from the branching unit, lowering rates and tension targets, and vessel/sheave geometry. **Run (quick model)** drives the analytic planner; **Verify (full solver)** re-runs the same inputs on the full solver. Its settings are saved separately from the main simulator.
- **Cable Route Workbench** – system-first management of cable segments, physical cable make-up and RPL revisions. The main tree is **System → Cable segment**: each segment contains an ordered cable make-up (one or more assembly placements with explicit joints) alongside its RPL revisions; the reusable assembly catalogue is available from **Manage assemblies…** instead of occupying a separate root branch. RPLs arrive through **Import RPL (Excel/CSV)…** (a guided wizard that detects the worksheet, layout, coordinate encoding, units and columns), **New RPL from route line or points (KML...)...**, **Import path file (.pthmdb)...**, or **Add RPL from layers** for a point/line pair already in the project; the RPL Manager edits positions on the map with live distances, bearings and slack. System pages use a **Table | Schematic | Endpoints** layout, segment pages **Table | Schematic | Compare revisions**. A system lists segment-level revision, assembly, section, length, per-cable-type length and status figures, and sums the cable types across the system (*LW 12.300 km · DA 4.100 km*). The system **schematic is where the topology is built**: open endpoints are amber and labelled with the RPL event at that end—right-click one, choose *Start connection from here* (or Shift+click), then click the other; right-click an endpoint to *Connect to…*, or to add a branching unit / beach manhole / joint already connected to it; right-click a node to disconnect a port, rename, add a branch port or delete; a BU's spare branches show as dashed stubs. **Add BU / node…**, **Connect endpoints…** (two lists side by side) and **Suggest connections…** (nodes and joints proposed from matching RPL endpoint events, e.g. two segments both ending at *BU-1*) cover the same ground from buttons. **Sections** expands every segment into its event-to-event RPL sections (cable type above, length below); each segment can also be expanded or collapsed on its own from its right-click menu. A segment lists its cable make-up, the selected revision's Positions and event-to-event RPL Sections, and revision history. Its schematic shows the physical assembly/joint chain—assembly name and per-type section lengths above each line, used length below—or, via the **Show** selector, the selected revision's RPL sections. Schematics are pan/zoom canvases, wrap long chains by default, provide a readable **Home** view plus an explicit **Fit all**, and build lazily. Detailed RPL editors retain configurable position/section/leg columns and revision-stable Start/End topology labels, with cached navigation. **Compare revisions** puts any two of the segment's revisions side by side: *Statistics* gives positions, legs, events, alter courses, cable bodies by type, RPL sections, start/end KP, route and cable length, slack and the route/cable length of every cable type, each with the change from A to B; *Positions* and *Legs* give the mapped differences. Positions are **mapped, not row-matched**: positions that can only be each other (same coordinate, or an event name unique in both revisions) anchor the mapping, the stretches between anchors are aligned on event text and separation on the ground, and the mapping is kept in route order, so inserting one alter course reports one addition rather than renumbering everything after it. Each matched pair says what changed (event text, position, KP, cable distance, depth, remarks) with the offset in metres and the KP shift; unmatched positions read as added or removed, and legs follow their endpoints (cable type, code, lengths, slack, protection, target burial). *Show changes only* filters the tables, double-clicking a position zooms the map to it, and the whole comparison exports to CSV.

  Workbench map layers mirror the tree: the **Cable Route Workbench** group holds a group per system, per cable segment and per RPL revision, with layers named *System · Segment · Revision · Lines / Points* so a revision is identifiable in any layer picker. Assessment and assembly-fit outputs join the revision they came from. Layers are placed on import and **File… ▸ Organise map layers** re-files an existing project (also done automatically after a rename or a change of system); a layer dragged out of the workbench group is renamed but left where it is, and layers are always matched by data source, so renaming one by hand breaks nothing.

  Cable types are coloured from the user's own palette first, then the built-in armour colours, then a colour derived from the type name. **File… ▸ Cable type colours…** edits that palette (stored in QGIS settings, so it follows you between projects) and applies it to the loaded workbench layers. A layer that already carries an RPL-shaped renderer — the style you saved as the GeoPackage default, or your own edits — is never overwritten when the layer is reloaded; only cable types that have appeared since get a category added. In this model, a cable segment is the stable route identity normally represented by one RPL; an RPL section runs between event positions; an assembly section is a homogeneous length within an assembly. No additional runtime dependency is required.

- **Planner** *(beta)* — build multi-resource planning scenarios, draw or link spatial tasks, turn route legs and selected waypoints into timed operations, and import whole/partial RPLs with cable-type speed mappings plus Lay/PLGR/Plough/ROV/Recover section assignments. Route and point sketches can snap to existing points/vertices and line segments, or accept an exact WGS84 latitude/longitude or KP on an existing route task. MS Project-style indentation turns a normal row into a calculated, collapsible group summary whenever following tasks are indented beneath it; a contiguous selection can also be wrapped in a new group directly. Vessels/resources are project-level and shared by every scenario (deleting a scenario never deletes them), each with its own colour, default speed, and start offset; resource lanes run concurrently while cross-resource predecessors coordinate SIMOPS. Scenarios can schedule forward from a start or backward from a required finish. Optional advanced controls add per-scenario absolute resource availability, FS/SS/FF/SF links, lag, date constraints, milestones, explicit positions on linked routes, critical-path float, baselines, and SIMOPS/resource warnings without changing the simple defaults. New tasks inherit the preceding task's resource and predecessor; after a line operation they reference its actual finishing endpoint as a point location. Task-table columns size to their contents by default and can be resized, drag-reordered, and shown/hidden from a header right-click, with the layout remembered per user. Double-click a row number (or right-click → Zoom to task) to zoom the map to a task; playback tints the rows of tasks under way, and a live totals row summarises span, duration, and fuel. The compact table displays measured nautical-mile distance and speed, supports undo/redo, and plans can be animated or copied into MS Project; tasks can also be imported from MS Project or CSV. Fuel planning: give each vessel Transit/DP/Anchor/Port burn rates (per 24 h, t or m³), a start fuel, and an optional cost per unit; pick a fuel mode per task and bunker on port calls, then track burned fuel and remaining-on-board per task plus a per-resource fuel report with run-dry warnings. Waiting/standby consumption is represented by an explicit task rather than implicit gap burn. Fuel ROB can optionally be shown in moving playback labels. Cable operations (load, lay, recover, discharge) track cable onboard per vessel, and a **Reports** window charts fuel, breakdowns, a progress S-curve, plan-vs-actual variance and milestones. Baseline/actuals tools record progress, actual dates, remaining duration, and timestamped operational-change notes. A per-user standard-tasks library includes operation type and inserts curated templates as ordinary editable tasks, with CSV import/export for sharing across an organisation; RPL operation mappings can also be saved as ordered ProtectionMethod rules.

- **Burial Planner** *(beta)* — a guided **Plan → Inputs → Burial Tools → Bathymetry Profile → Ground Model → BAS → Exclusions → Risk Profile → Installation Paths → Plan Builder → Review** workflow that turns an RPL plus survey data into a burial plan. Inputs owns route, scope and source selection; Bathymetry Profile prepares persistent depth/longitudinal/cross/absolute terrain data; Ground Model holds the soil units along the route by depth below seabed (imported from a CSV/XLSX interval or horizon table, or edited in place) on a plot KP-linked to the bathymetry profile, with a project-wide soil-class palette and a check that a unit exists at the target burial depth over the scope; BAS holds the Burial Assessment Study's conclusions as an editable spreadsheet-style KP-range register whose columns are whatever the study delivers (required and achievable depth of lowering, risk category, soil province…), imported from CSV/XLSX with the same KP re-referencing, with a scope-coverage strip. Both draw on the map as per-plan layers beside the route (ground-model class ribbons to port, BAS rows to starboard, sections on the line) with Show-on-map toggles; Exclusions owns its ordered rules plus coarse spatial-search/sliver controls; Plan Builder owns candidate-section length and event/section refinement. A plan can mix burial tools — Plough (PLDN/PLUP), PLB trenchers/ROVs and Mass Flow Excavators (Start/End PLB) and Inspection — with each section labelled by its own tool, and an existing plan can be imported from a KP-range table or from an RPL's boundary events or protection-method column (*Plan Builder ▸ Import plan*). Plan KPs follow the RPL, including an RPL that starts at a non-zero KP, and *Set route* can move a plan to another RPL revision while keeping its seabed positions. Because ground models, BAS reports and client mark-ups quote KPs against older RPL revisions, the Ground Model import and its *Re-reference KPs…* action state which revision the source KPs follow and map them onto the plan's route — by walking the other Workbench revision's geometry and projecting it onto the current one (re-routed stretches are detected and bridged), by matched KP pairs from the change note, or by a constant shift — keeping the delivered KPs and revision on every unit and flagging where the mapping is extrapolated, bridges a gap or stretches a unit. Installation Paths applies the selected tool configuration's minimum turning radius to every non-collinear RPL geometry vertex: tangent circular fillets are the default, while an exact-through bounded-curvature mode can turn out and back in through every course-change point; interacting turns are solved together. The radius can be banded by water depth (each course change samples the registered bathymetry; the tool's own radius stays a hard floor), and a per-course-change depth-difference audit compares bathymetry at the tool path's actual position with the RPL vertex. Plough plans can additionally apply a constant or water-depth-varying horizontal layback profile to generate a planning tow-point/barge track, checked against a registered vessel's minimum turning radius; tool and vessel DXF outlines ride the generated tracks in the map overlay. All burial analysis and KP references remain on the RPL — the installation path is a derived operational-geometry product. Tool path, barge track and course-change diagnostics are persisted, fingerprinted current/stale, independently toggleable map layers and are included in the HTML report. The criteria stack remains the source for Exclusion Areas, Constraint Influence Zones, Screening annotations, Insufficient-Information ranges and candidate burial sections. Analysis runs in the background with cancellation, scoped caching and 0.1 m boundary refinement. The target burial depth has a plan default plus optional KP-range overrides (entered, picked on the map or read from the RPL legs), which the ground model, Plan Builder, exports and report follow. Inputs are registered many at a time from a searchable, geometry-filtered layer picker (*Manage inputs…*), bathymetry is set in *Configure bathymetry…*, and the Inputs tab shows whether each input still resolves and which criteria use it. The latest Exclusions recompute and Risk Profile scans are saved with the plan and marked out of date, per criterion or check, when their settings change; the bathymetry profile's currency is judged on the route geometry and each bathymetry table's content, and an out-of-date profile says why. The profile's *Overlays* menu shows or hides each overlay (including a Risk Profile hazard strip) and filters Insufficient Information by the criterion that had no data. **Beta — sanity-check the output against your own data and established methods before using it for any operational or engineering decision.** No criteria, turn radii or layback values are shipped; all engineering limits are user-entered with source references.

- **Cable Lay Data Explorer** — a standalone window for QC and analysis of cable-lay data imported with the Cable Lay Data Import tools. **Project** manages the project's cable-lay GeoPackage (new, open, duplicate, delete, compact, standard-layer inventory); **Manage** works per imported source file (fix a wrong start date, mark rows active / standby / excluded, remove rows, fill time gaps from a second source without deleting anything, import history, import files into any layer, enable the QGIS Temporal Controller); **QC**, **Inspection** and **Processing** tabs run lay-data checks, threshold and off-line-distance inspections, and produce as-laid listings and an as-laid RPL. A virtual data table and configurable multi-series plots (dual axes, slope series, event and QC overlays, time axis) stay in sync with the map in both directions; Ctrl+Left / Ctrl+Right steps record by record, and *Active rows only* hides standby and excluded rows without changing the data.

### Distance & CRS methodology

- **One KP definition.** KP is chainage measured by the plugin: geodesic segment lengths on the **WGS84** ellipsoid (independent of the project's ellipsoid setting), with positions interpolated along each segment as stored, so KP → point → KP round-trips exactly. Multi-feature routes are joined in `SeqNo` / layer order, without noding or re-ordering. An RPL contributes only its start KP (normally 0); the KPs printed in an RPL are checked against the measured KPs, never used for positions.
- **Cartesian option.** **Subsea Cable Tools ▸ KP settings…** switches KP plugin-wide to planar grid distances in a chosen CRS, else the project CRS when projected, else the route's UTM zone. The KP Mouse Tool, Depth Profile, KP Plotter, Planner and the RPL tools follow the setting, and it is the default *Distance mode* of every KP processing tool. Burial plans keep their own KP mode, so changing the global setting never renumbers a plan.
- **Layer-CRS measurement.** Tools measure in the layer's own CRS to avoid silent unit confusion. Mismatched inputs (e.g. KP Plotter line vs project, Nearest KP points vs paths, Place KP Points sample raster) are auto-reprojected with a feedback note. The exception is "Translate KP Between RPLs", which still requires both layers to share a CRS.
- **Planner playback follows the planned feature.** Planner route lengths and speed/duration calculations follow the plugin's KP measurement, segment by segment. Playback points and completed/remaining bands are clipped from the stored route in the current map CRS, so they do not replace a sparse sketched edge with a visually different great-circle arc. CRS changes are handled by transforming the route before display.

### Slope methodology

All profile tools use `bathymetry_sampling.py` and `slope_utils.py`. Depths are normalised to metres, positive down. Longitudinal slope is `atan2(-Δdepth, horizontal distance)` (positive = shoaling along increasing KP); cross tilt is positive when deeper to starboard. Depth Profile can invert its reported longitudinal sign. Burial travel direction swaps directional limits.

- **Source conventions:** use **Source conventions…** in Depth Profile, **Bathymetry source conventions…** in KP Mouse configuration or Burial Planner's Bathymetry Profile tab. Select depth/elevation, metres/feet, a datum label, bilinear/raw sampling, and an optional native cell size for legacy mosaics. Settings belong to each project layer and are shared by the tools. Auto infers an offshore vertical convention once per source; explicitly choose a convention near zero or for mixed-sign data. A datum label does not perform a vertical datum transformation.
- **Rasters:** no-data-aware bilinear interpolation at native cell centres is the default. Raw nearest-cell sampling remains available for inspection. No extrapolation beyond contributing native cells. The longest native cell dimension is converted to metres, including geographic and feet-based CRSs.
- **Longitudinal baseline:** automatic raster slope spans at least two native cells and two median station intervals within each contiguous source run, widened over repeated raster terraces (see [Terraced grids](#terraced-grids)). An explicit slope length is a fixed physical baseline. At the ends it shifts inward while retaining its full length; insufficient coverage or a length below two native cells yields no slope. Missing/nonfinite data and source changes break the calculation. Display sampling density is not a vehicle footprint.
- **Contours:** retain exact line crossings and linearly interpolate between valid brackets. Coincident identical observations collapse; conflicting depths become gaps. There is no endpoint extrapolation, no nearest-contour staircase in longitudinal profiles, and no smoothing spline. Automatic contour slopes describe exact crossing intervals. **Contours only** in the KP window provides an explicit comparison with contour-based lay software; matching that software still requires checking its settings and delivery.
- **Cross profiles:** overall **cross tilt** is the supported endpoint difference across the requested width, not the steepest seabed wall. **Maximum local cross slope** is reported separately in Depth Profile and Burial Planner, and is available as a burial criterion. Raster cross profiles retain intermediate coverage and native-resolution slopes. Contour cross profiles search to twice the requested half-width for bracketing crossings and evaluate only within the requested width. Sparse, one-sided or incomplete coverage is insufficient information; no regression extrapolation or deletion of real repeated contour crossings. Maximum local slope refers to the resolved profile, not unknown detail between observations.
- **Merges:** new MBES mosaics have a `.sources.json` companion listing native inputs and their conventions. Engineering profiles read those original files, finest first, retaining native resolution and source boundaries; keep the companion and original files accessible. For a persistent mosaic, save imported source grids permanently before merging and retain the output TIFF and its `.sources.json` sidecar — saving only a temporary mosaic does not preserve its native source dependencies. Display overlap priority in the mosaic may differ. Existing mosaics without a companion need a manually specified native resolution, and cannot recover lost provenance automatically. Verify vertical datum agreement between surveys.
- **Burial profiles:** source IDs, native resolution and local cross maxima are stored with samples. The new calculation version and source settings participate in currency checks, so older profiles need rebuilding. Hover, plotted slopes and rules share the supported calculations. Longitudinal rule boundaries follow the stored supported slope series; no second resampling calculation. Missing components make absolute slope unavailable in the pane and insufficient information for absolute-slope rules.
- **Seabed length:** sums within valid same-source coverage using route-chainage distances; missing stretches and source seams are excluded. Covered plan length is reported separately. This is sampled seabed length, not a claim about unresolved roughness.

### KP Mouse quick profile

Start a range line on the map and press **D** to show/hide its profile. **Space** or **Freeze** locks the line and displayed data before moving into the plot. The depth view defaults to **True scale 1:1**, accounting for horizontal/vertical unit conversions; uncheck it to allow vertical exaggeration. The slope-angle panel retains its independent vertical scale. Hovering the profile draws a matching cursor on the range line on the map; while the profile is frozen, moving the pointer along the range line drives the plot cursor.

**Measuring.** **Right-click inside the depth plot → Measure** freezes automatically: choose a source, optionally snap to the profile, then click two points. An elastic dashed preview follows the pointer, and each measurement draws a labelled triangle: horizontal **X** and vertical **Y** legs, and a diagonal showing the straight-line **Length** and the unsigned endpoint **Angle** (0–90°), calculated in metres independent of display units or vertical exaggeration. Coincident endpoints have no defined angle, and the endpoint angle does not report the maximum terrain slope in between. Repeat to retain multiple measurements; the table shows Length, X, Y and Angle. Metres are the default; horizontal and vertical units can be changed independently, and measurements remain internally in metres. Completed measurements have draggable circular endpoints: dragging updates the triangle, table and exported values, and snapped measurements stay on their original source and stop at gaps. Changing source or snapping cancels an unfinished measurement.

**Delete / undo** removes the selected measurement (or the last); **Clear measurements** starts again. Drag to pan and scroll to zoom, including while measuring; drags do not place endpoints. Uncheck Measure in the right-click menu to stop measuring. **Escape** cancels a pending endpoint, leaves measurement mode when no endpoint is pending, and otherwise closes the window. **Resume** clears annotations and reconnects to the map. Clicking the map clears the range/profile unless **Keep on map click** is selected for a frozen profile. Export/unit dialogs do not close the profile on focus loss.

**Route KP labels** labels the distance axis with the nearest route KP in kilometres: ticks are placed where the range line's nearest-route KP crosses round values (…0.100, 0.250, 0.500, 1.000…, chosen from the zoom level), and never inside a jump where the nearest route segment switches. The axis itself stays in physical range-line distance, so widths remain correct, and oblique, curved and transverse relationships may give unevenly spaced or repeated KP labels; this is a projected KP ruler, not a resampled longitudinal route profile. The choice is remembered.

**Exports.** **PNG** captures both plots, annotations and route-KP labels; **CSV** contains depth observations, validity/source/native resolution, actual slope baselines, projected KP, the terrace averaging suggestion, the axis mode and measurement rows in explicit SI units (including the signed `slope_deg` and the unsigned `angle_deg`). Exports freeze the profile. Shading and anti-aliasing improve presentation without changing the calculation; the raw-cell view remains available.

#### Terraced grids

Automatic raster slopes check each continuous source run for repeated flat terraces. Where at least three interior plateaus span four or more sample gaps, exceed two native cells and most intervals are flat, the averaging baseline expands to twice the longest qualifying plateau spacing. This reduces step-edge spikes from finely resampled coarse grids without changing depth values. It is a pattern-based averaging scale, **not** a determination of native resolution or a guarantee of maximum local slope. Real repeated terraces can also trigger it; inspect the source and select an explicit slope length for engineering comparisons. Isolated cliffs, continuous slopes, contour intervals, missing-data boundaries and source boundaries retain their existing handling. The same calculation serves Depth Profile and Burial Planner.

The quick profile reports detected terraces, the actual averaging length and a warning when an explicit length is shorter. Recovering a smooth physical surface requires original survey grids or rebuilding the raster from original soundings with a suitable interpolation method; a finer output pixel alone is not higher-resolution evidence.

### Dependencies

The plugin vendors `openpyxl`, `pyqtgraph`, `et_xmlfile`, `access_parser`, `construct` and `tabulate` under `lib/` (versions and licences in `lib/VENDORED.md`). The folder is appended to `sys.path` as a fallback, so copies that ship with the host QGIS Python take precedence. End users do not need to install pip packages for typical workflows; plugin plotting tools use the vendored `pyqtgraph` backend.

The MDB import works out of the box on any platform via the vendored pure-Python `access_parser` reader. If a particular file cannot be read that way, it falls back to ODBC, which requires Windows + the Microsoft Access Database Engine ODBC driver and `pyodbc` available to the QGIS Python.

## Development

### Running the tests

There are two runners, both run from the plugin folder:

- **QGIS-free suites** (calculation cores, burial generation/events/IO, rules engine, RPL import core, …) run under plain Python; NumPy is optional but exercises the vectorised paths. GitHub Actions runs these on pushes to `main` and on pull requests. On a Windows console, set `PYTHONIOENCODING=utf-8` if a test name with a non-ASCII character raises `UnicodeEncodeError`.

  ```
  python tests\run_pure_tests.py --fast          # skip the slow lay-simulator (test_v3_*) suites
  python tests\run_pure_tests.py                 # everything
  python tests\run_pure_tests.py -k burial       # suites whose name contains "burial"
  ```

- **QGIS smoke suites** (Processing algorithms, docks and dialogs, GeoPackage stores, distance/KP utilities) need a QGIS Python. The runner boots a headless `QgsApplication` itself and works under both QGIS 3.22+ (Qt5) and QGIS 4.x (Qt6); run it under both before claiming compatibility with either.

  ```
  "C:\...\OSGeo4W\bin\python-qgis.bat" tests\run_qgis_smoke_tests.py --fast   # everything except the lay group
  python-qgis.bat tests\run_qgis_smoke_tests.py                               # full run
  python-qgis.bat tests\run_qgis_smoke_tests.py --only lay                    # just the lay simulator / catenary group
  python-qgis.bat tests\run_qgis_smoke_tests.py -k profile                    # checks whose label/module contains "profile"
  python tests\run_qgis_smoke_tests.py --list --fast                          # show what would run (no QGIS needed)
  ```

Most of the run time is the cable lay simulator and catenary group (`lay`); `--fast` skips it for changes that do not touch `catenary/` or the lay-simulator tools. Each check prints its duration and the run ends with the slowest checks. `plot_widget.py`, `slope_utils.py` and `qgis_compat.py` are shared with the catenary tools, so changes there still warrant a full run. `tests/check_qgis_compat.py` is a static Qt5/Qt6 and QGIS 3/4 compatibility check.
