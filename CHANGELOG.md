# Changelog

- **Workbench — RPL points classify as assembly, geographic, or both (the "installation" bucket is gone):** every RPL point has a place on the map; the classification now answers *what else it is*. Two natures, not mutually exclusive: an **assembly component** is a physical part of the cable (repeater, equaliser, joint, branching unit, armour transition) that moves with the assembly if the make-up changes, while a **geographic reference** (crossing, alter-course, route branch, water-depth mark, operational mark, maritime boundary) stays put on the map. One event text can be **both** — "JT-3 / AC12" is a joint currently coincident with an alter-course position: reflow the assembly and the joint moves, the AC stays. The classifier evaluates every rule instead of stopping at the first match, taking each nature's subtype from its own best-priority rule; the old third "installation" bucket is removed (its marks — PLDN/PLUP, burial, SOL/EOL — are geographic; armour transitions move to assembly, where they belong), and legacy registries normalise on read. Subtypes are a free vocabulary seeded with sensible defaults (equaliser and maritime-boundary rules are new) and fully user-editable in a new **Edit event classification rules…** dialog (Assembly Manager → Import menu) — pattern, nature, subtype, priority per row, with the existing reset-to-defaults beside it. The RPL Manager points table gains a **Category** column (e.g. "Assembly — joint", "Geographic — crossing", "Assembly + geographic", with unmatched events flagged), the extract-from-RPL review offers the three-way choice with clearer wording, and segment schematics colour both-nature events distinctly. Unmatched events still default safely — to geographic now — and never silently become a body. This classification is the groundwork for nature-aware editing (assembly points riding make-up changes while geographic references hold position).

- **MBES tools — true multi-file XYZ import, exact cell registration, and a merge that never degrades resolution:** *Create Raster from XYZ* now takes real multiple-file selection (the comma-separated single-field workaround still parses for old scripts); each file keeps its own auto-detected grid size, one CRS applies to the whole batch, and in a batch a bad file is skipped with a warning instead of aborting the rest. Accuracy fixes: XYZ coordinates are now treated as cell centres — previously the raster extent ran to the outermost points, shifting every cell half a pixel and sometimes dropping the edge row/column; header lines ("Easting Northing Depth") and semicolon/tab delimiters no longer break the parse; and a raster-size guard turns a mis-detected grid size on non-gridded data into a clear message instead of a memory-exhausting run. Reliability: unique temp names (parallel runs no longer collide), no private `tempfile` API, temp CSVs deleted per file so long batches don't fill the temp drive, and compressed outputs are tiled for faster display. *Merge MBES Rasters* is rebuilt on `gdalbuildvrt -resolution highest`: the old `gdal_merge` silently resampled everything to the **first** input's resolution, so merging a 0.25 m tile into a 1 m mosaic could throw the fine detail away depending on selection order — the merged raster now always keeps the finest input resolution, respects each file's own NoData, and refuses mixed-CRS inputs with a clear message. Both tools use QGIS 3/4-safe enum aliases and add no dependencies. End-to-end coverage (two grids at different resolutions through create → merge, value fidelity checked per cell) in `tests/test_mbes_xyz_tools.py`.

- **Workbench — RPL from a bare route line (KML etc.), revision order that survives out-of-order imports, and a real window when floated:** a third import path joins the Excel/CSV wizard and *Add RPL from layers*: **New RPL from route line (KML...)...** (Workbench New menu and the cable segment context menu) registers a plain line — any line layer already loaded in QGIS, or a browsed KML/KMZ/GPX/GeoJSON/SHP file — as a new RPL revision of a cable segment. One position per vertex (route ends labelled A End/B End), zero slack, distances/bearings/cumulatives computed by the RPL engine, and registration goes through the same commit path as the wizard, so revision labels, duplicate-label refusal, supersedes lineage, unique layer names and topology endpoints behave identically. Ambiguity is refused rather than guessed: a layer with several line features needs exactly one selected, and multi-part lines must be merged first. Revision ordering is now numeric-aware: receiving *Rev 3* before a corrected *Rev 2* no longer makes Rev 2 the segment's "latest" revision (unnumbered labels such as *As-laid final* sort after all numbered ones by creation time) — this drives the latest-revision shortcuts, supersedes defaults and revision history everywhere. And the Cable Route Workbench dock, when floated, is now a real window with minimise/maximise buttons — the same pattern as the Planner and Burial Planner — for keeping it full-screen on one monitor with the map on the other. Headless coverage in `tests/test_rpl_from_line.py` plus an out-of-order lineage check.

- **RPL Manager — survives its layers being deleted, and 'Add RPL from layers' refuses to duplicate a registered revision:** removing an open RPL's point/line layers from the project (or closing the project) no longer leaves the RPL Manager holding a dead edit session — every later interaction (selecting another RPL, closing the panel, New RPL revision, Issue) raised `RuntimeError: wrapped C/C++ object of type QgsVectorLayer has been deleted` and left the panel blank until QGIS was restarted. The layer sync now detects deleted layer objects and the panel silently drops the defunct session (its edit buffers died with the layers, so there was nothing left to save); reselecting the RPL reloads its layers from the workbench GeoPackage. Separately, the *Add RPL Layers to Workbench* tool now refuses inputs that are already registered workbench layers of the target GeoPackage — running it on the current revision's own layers silently created a "new" revision containing the old revision's data. The error message points to the intended flows: **Import RPL…** for a received file, **New RPL revision…** to duplicate the current revision for editing.

- **Cable Route Workbench — guided systems, physical cable make-up and readable schematics:** the Workbench uses one stable **cable segment** for the route identity normally represented by an RPL, with RPL revisions beneath it; **RPL sections** are derived between consecutive labelled event positions, point-to-point calculation rows are explicitly **legs (advanced)**, and **assembly sections** remain homogeneous lengths inside an assembly. The main tree is now System → Cable segment: the former Assembly Library root is removed, while each segment exposes an ordered **Cable make-up** of one or more reusable assembly placements with explicit joints. A secondary **Manage assemblies…** catalogue handles reusable definitions. Schema v5 adds revision-ready make-up/item tables and seeds existing latest-RPL fits during migration without changing the geometric fit records; ambiguous multi-fit order is retained but flagged for review. Selecting a system or segment opens a guided **Table | Schematic** overview. The system table lists segment-level revision, assembly count, RPL-section, length, cable-type and status figures; the segment table adds cable make-up beside cached Positions, event-to-event RPL Sections and revision history. The segment schematic is intentionally the physical assembly/joint chain rather than every RPL event: assembly name/type is above each line and used length below. All SLDs are simple pan/zoom node-and-line canvases—the old bar plot is removed—with default wrapping, DPI-safe visible controls, a readable **Home** viewport and a separate **Fit all** overview. Detail labels progressively hide when a large system is zoomed out, and schematics/tables are built lazily. Configurable imported columns, revision-stable Start/End topology, cached summaries, batched tree reads and reused layers/models keep navigation responsive. No new dependencies; Qt5/Qt6 compatible.

- **RPL import — cumulative cable distance beside cable span distance:** when an unmerged/grouped source header names the cable-span column fully but labels the following column only *Cumulative* or *Total*, detection now restores the missing cable context from guarded adjacency. The fallback only applies when route KP and cable span are already mapped, the immediately following column is unused, its header expresses cumulative meaning, and its numeric content is predominantly monotonic; adjacency alone never assigns a field. Positive and negative regression cases extend the pure import-core suite.

- **Planner — import an RPL file without leaving the planning workflow:** the Planner action is now named **Add from RPL…** because it can create tasks from an existing source or a new file. Its dialog explains and refreshes the two existing source types (registered Workbench RPLs and line layers already loaded in the QGIS project) and adds **Import RPL file...**, which opens the guided Excel/CSV RPL wizard, registers the result in the project Workbench, returns to Planner, and selects the newly imported RPL automatically. A useful empty/error state replaces the previously blank source picker, and OK remains disabled until the selected source produces importable task geometry. Headless QGIS coverage exercises the empty state, refresh, and wizard handoff.

- **Burial Planner — live tool footprint on the map + Place Outline Along Route (KP):** a new **Tool outline** toggle above the profile pane draws the effective burial tool's footprint on the map canvas — to scale, rotated to the local route heading — at whatever KP you hover or select on the profile: instant scale context for judging seabed features against the vehicle. The footprint follows the plan (each burial section's assigned tool, else the plan default) and needs a DXF footprint registered on the Burial Tools tab; it is a transient overlay (rubber band), never a layer. Placement is metre-true: each KP is placed in its local UTM zone with the heading measured between projected route points, so grid convergence is handled implicitly. The same engine ships as a Processing algorithm, **Place Outline Along Route (KP)** (Other Tools): place any body-fixed outline from Import Ship Outline (DXF) — ship or tool — at a KP list or a start/end/interval series along any route, ellipsoidal KP chainage matching the plugin's other KP tools, output in EPSG:4326 with kp / heading_deg / source attributes for chartlets. Placement maths are pure and headless-tested. No new dependencies; Qt5/Qt6 compatible.

- **Burial Planner — one Trencher method, bulk tool assignment, simpler A/C check:** the ROV-jet method is folded into **Trencher** (schema v7, pre-migration backup): new plans offer Plough or Trencher only, and existing `rov_jet` plans/sections/tools/rule filters migrate automatically — labels change from JET_START/JET_STOP to TRENCH_START/TRENCH_END (stored event types were always the generic BURIAL_START/END, so nothing else moves; old CSV exports with JET labels still import). Plan Builder: right-click a multi-selection → **Set tool** assigns a tool *and* configuration to every selected burial section in one gesture (submenu per tool listing its configurations, plus "Plan default"), matching the existing bulk conclusion/confidence/skip-handling actions. Risk Profile: the alter-course check is now one question — **flag course changes of at least X° at risk level Y** (main consequence: running off route at the turn) — replacing the attribute-rule grid for turns; existing checks with turn_abs rules keep scanning unchanged until re-saved, and the editor refuses an unassigned risk level (which would record nothing). No new dependencies; Qt5/Qt6 compatible.

- **Burial Planner — Burial Tools registry, trencher method, per-section tool assignment, sea level on the profile:** a new **Burial Tools** tab registers the project's burial vehicles once per GeoPackage (shared by every plan, the Planner-vessels model — schema v6, `bp_tool`): name, type (Plough / ROV jet / **Trencher**, new plan method with TRENCH_START/TRENCH_END event labels and TS section codes), a source reference, free-form operating configurations (e.g. "Jetting 3 m" vs "Passive 2 m share", each with user-entered track width, bearing length, min turning radius, max burial/water depth — no engineering values are shipped), and an optional plan-view footprint imported from a **DXF** via the existing OGR reader (normalised to a body-fixed metre frame, CRP at origin, stored as WKT on the tool row so a registry travels without the DXF). Registries export/import as versioned JSON (the rule-set format precedent). The Plan tab sets the plan's **default tool + configuration** (recorded in `params_json`, change-logged, does not mark the plan stale); the Plan Builder sections table gains **Tool / Tool config** columns on burial rows — blank inherits the plan default, an explicit assignment also stamps the section's reserved `method` column and carries over regeneration like conclusions do ("plough X jetting here, passive 2 m share there"). The resolved tool appears in the sections map layer, CSV export and HTML report; deleting a tool never edits plans (assignments render "(unregistered tool)"). Method vocabulary (event labels, section-kind labels, ref codes, legends) is consolidated in `burial/schema.py` — the Plan Builder and report no longer keep duplicate copies, and remaining hardcoded PLDN/PLUP UI strings resolve per method. Workbench↔Burial method ids are normalised (`"jet"` ↔ `"rov_jet"`) at rule copy/JSON import **and** healed at read time, so Assessment rules tagged `jet` no longer silently skip in an ROV-jet plan; the migration also rewrites rule method filters that covered every pre-v6 method to the explicit all-methods marker, so existing exclusion criteria keep firing in a Trencher plan instead of being silently filtered out. The profile pane gains a **Sea level (0 m)** toggle (dashed line; the depth axis auto-range includes the surface while shown — groundwork for deck-transit modelling). Fixed: Import Ship Outline (DXF) crashed when an output CRS other than EPSG:3857 was chosen (`QgsGeometry.transform` was handed a CRS instead of a `QgsCoordinateTransform`). Existing GeoPackages migrate automatically with a pre-migration backup. Headless coverage in `tests/test_burial_tools.py`. No new dependencies; Qt5/Qt6 compatible.

- **Burial Planner exclusions — separate depth/slope criteria, slope components, and a safe fresh restart:** the combined "Water depth / slope threshold" criterion splits into two Add-menu entries with their own dialogs — **Water depth** (condition + value only) and **Slope** — while sharing the stored rule kind, so existing rules open in the right dialog unchanged. The WD-band grid now appears only on the Slope dialog, where it reflects its real use (burial-tool slope capability varying with water depth; a WD band on a depth criterion was circular). Slope criteria gain a **component** selector: **longitudinal** (along route, signed limits available), **cross** (across route, from the stored profile's ± cross-offset samples — the limit applies to the magnitude, leaning either way) or **absolute** (combined gradient, matching the profile pane's Absolute trace) — cross/absolute need a profile built with a cross offset and surface unevaluable stations as Insufficient Information; boundaries interpolate at profile resolution. The polygon corridor field is relabelled **"Distance each side of route"** with the proximity rule's tooltip likewise clarified: the value is measured from the route centreline, so the full searched corridor is twice it. Plan Builder documents the regeneration contract on Generate plan (manual/locked/confirmed events and section curation are preserved; only auto candidates are replaced) and adds **Regenerate fresh…**: after a confirmation listing exactly what will be discarded (manual/imported events, confirmations, locks, curated sections — client burial-proposal events are kept as reference unless also ticked), the plan is rebuilt purely from the Exclusion stack; the previous state is recorded in the change log so the action can be rolled back from Review & Export. No new dependencies; Qt5/Qt6 compatible.

- **Burial Planner — WD-band grid editor and skip-handling auto-assign:** water-depth-banded limits on threshold criteria are now edited in a grid (Min WD / Max WD / Limit, with down/up-slope limit columns appearing for signed slope; blank cells leave that side open, first matching band wins by row order) instead of a raw JSON field — the stored `bands` format is unchanged, so existing rules load as-is. Plan Builder gains **Auto-assign skip handling…**: skips up to a user-entered length become *Mid-water transit*, longer skips *Recover to deck*; the threshold is your operational policy (no default is prescribed, the value is remembered per machine and recorded in the change log), skips you already assigned are kept unless overwrite is ticked, and the whole assignment is a single undoable edit (Ctrl+Z). No new dependencies; Qt5/Qt6 compatible.

- **Burial Planner exclusions — extensions you can see, water-depth scaling, and route corridors:** the per-rule bars on the Exclusions tab (renamed from *Fires* to *Excluded sections*) and the Coverage column now show each criterion's **resolved** footprint — extension buffers included — so an extended Exclusion Area no longer looks unextended on screen (the extension was always applied to the built plan; only the display ignored it). The extension itself is upgraded from one symmetric distance to per-side **before/after** values that follow the direction of installation, in either **fixed metres** or a **water-depth multiple** (e.g. 1 ×WD each side, evaluated at the footprint boundary from the stored plan profile; legacy `extend_m` rules load unchanged). Seabed-soils polygon criteria gain an optional **route corridor**: exclude where a matching polygon comes within a fixed distance *or* a water-depth multiple of the route (e.g. a WD-dependent lay corridor), with acquisition, caching (bathymetry participates in the cache key for ×WD corridors) and 1 m boundary refinement all evaluating the identical condition; the default remains the route centreline test. Exclusions tab UX: right-clicking a criterion lists its excluded KP ranges with *Go to* map/profile zoom; a **Show Exclusion Areas on map** toggle previews the resolved excluded (red) / screening-flagged (orange) ranges as temporary highlights before any plan is built; an **Excluded sections…** dialog tabulates every resolved range with the criteria that triggered it and exports to CSV; and the redundant *Apply & recompute* button is gone — *Recompute* applies changed sampling parameters itself (criterion edits still recompute automatically). Plan Builder: Plough Skips draw as **solid** red lines on the map (Insufficient Information stays dashed grey), and the sections table gains a **Skip handling** column (TBC / Recover to deck / Mid-water transit, plough plans; schema v4 adds `bp_section.skip_handling`, carried across regenerations and included in the sections layer, CSV export and HTML report). No new dependencies; Qt5/Qt6 compatible.

- **Burial Planner workflow separates bathymetry preparation from exclusions:** the guided tabs are now Plan → Inputs → Bathymetry Profile → Exclusions → Plan Builder → Review. Inputs selects route/scope/source layers; the new profile tab explains and owns Profile step, Cross offset, resolved station count/slope spans, stored-profile state and explicit background rebuilding. Exclusions retains only Sample step, Sliver tolerance and fixed boundary refinement alongside the rule stack. Minimum candidate-section length moves to Plan Builder and is saved when Generate is clicked. The first profile is no longer sampled silently before its settings can be reviewed, and depth/slope analysis redirects to the profile tab when the stored data is missing or stale.

- **Burial Planner local-slope screening no longer flattens short steep terrain:** Auto longitudinal slope now uses the persisted bathymetry profile resolution (normally the raster cell size) rather than the unrelated coarse rule-search step. For example, a 25° face about 25 m wide is no longer averaged across the default 100 m window into roughly 6.6°. The slope panel and crosshair use the same local scale and state their baseline; setting a rule's *Slope evaluation length* remains an explicit vehicle-footprint average. Auto cross slope likewise uses the profile step at each side, while an entered cross offset represents the plough's half track width. Derived slope arrays are cached per evaluation length, profile resolution participates in rule cache keys, and the non-UI acquisition path can still sample at the bounded profile resolution when stored data is not injected. No new dependencies.

## [Unreleased] — Beta integration

### Added

- **Burial Planner (beta)** (`burial/`, Experimental toolbar menu): a dockable workflow tool that produces a burial plan for a cable route — which sections will be buried (plough or ROV jet), where burial starts and ends (PLDN/PLUP in plough mode, JET_START/JET_STOP for ROV jet), and why the remaining sections are skipped. An ordered stack of exclusion criteria (water depth / slope thresholds incl. signed direction-aware limits and optional WD-banded limits, crossings/proximity with per-feature buffer overrides, seabed-soils polygon classes, KP-range tables, manual ranges) is resolved over route + survey data into Exclusion Areas, Constraint Influence Zones, Screening annotations (which flag but never exclude), Insufficient-Information ranges where depth data has no coverage, and candidate sections with auto-placed boundary events — refined to 1 m by bisection on the underlying predicate rather than brute-force dense sampling. Plans persist in a dedicated per-project GeoPackage (`<project>_burial_plans.gpkg`) with styled sections/events map layers, a synced longitudinal profile pane (exclusion shading, event markers draggable in the profile, crosshair KP/depth/slope readout, map-canvas hover marker), event/section tables with confirm/lock/split/merge/conclusion workflows, an append-only change log with exact rollback, CSV export/import (events round-trip, KP-range lists, client burial proposals with a generation diff), and rule-set JSON export/import plus lossless rule copy from Workbench assessments. All analysis runs in a background `QgsTask` scoped to the plan's KP window with per-rule result caching — editing one rule re-acquires only that rule, and a cancelled run resumes from the warm cache. Built on the shared Workbench rules engine, which gains scope-limited sampling, signed slope, WD bands, per-feature buffers, no-data intervals and pure interval ops (subtract/dilate) — Assessment behaviour is unchanged by default (covered in `tests/test_rules_engine.py` / `test_rules_inputs.py`); the Assessment panel's overview/fire-bar widgets are factored into shared `workbench/kp_bars.py`. Headless coverage in `tests/test_burial_events.py`, `test_burial_generation.py`, `test_burial_io.py` (incl. a no-new-dependencies import scan), `test_burial_store.py` and `test_burial_task.py` (incl. an end-to-end snapshot → task → generation run). Beta: sanity-check outputs against your own methods before operational use; no proprietary criteria values are shipped — all limits are user-entered with a source-reference field. Implementation judgement calls are recorded in `DECISIONS.md`.
- **Burial Planner — sample once, plan fast (persistent plan profile):** bathymetry is no longer resampled on every profile refresh or analysis run. One sampling pass per plan — depth along the scope plus depths at a configurable ± cross offset either side of the route — is persisted in the plan GeoPackage (`bp_profile`, schema v3, `burial/profile_data.py`), stamped with the route and bathymetry-input fingerprints, the scope and the cross offset it was built with. The profile pane displays the stored samples instantly on plan open; threshold-rule analysis consumes them directly instead of resampling; and event editing never touches bathymetry at all. The first build runs automatically in the background for a plan that has never been sampled; after that, any change to the route, bathymetry inputs, scope or cross offset marks the profile **stale** (amber status naming what changed) and sampling reruns only when *Resample profile* is clicked — deliberately "slower once, then fast while building and editing the plan". Duplicating a plan carries the samples across; an empty sampling result never overwrites stored samples. Covered by `tests/test_burial_profile_data.py` (pure), plus profile persistence and stored-sample analysis-injection checks in `tests/test_burial_store.py` / `test_burial_task.py`.
- **Burial Planner — slope panel (longitudinal / cross / absolute):** a toggleable second plot under the depth profile, x-linked to it, shows three slope traces built from the stored plan profile: **longitudinal** (signed, plugin convention +ve = up-slope, measured over ± the analysis step), **cross** (signed, +ve = deeper to starboard of the direction of installation — B→A plans flip the sign because the vehicle's starboard is the other side), and **absolute** (magnitude of the combined gradient, `atan(√(tan²long + tan²cross))`; falls back to |longitudinal| where cross samples are missing). Cross slope is a two-point difference across the ± cross offset — set the offset to the vehicle's half track width on the Exclusions parameter row (*Auto* uses the analysis sample step). Slope maths are pure (`burial/profile_data.py`) and headless-tested, including the sign conventions and the direction flip.
- **Burial Planner — dragging a PLDN/PLUP on the profile now asks for a justification:** the same optional-reason prompt as table edits (Cancel aborts the drag and snaps the line back; OK with empty text records the default "profile drag"), so decision rationale is captured in the change log for profile edits too.
- **Burial Planner — HTML report export** (`burial/report.py`, Review & Export tab): one self-contained HTML file (inline CSS, base64-embedded snapshot of the profile pane) carrying the plan header and status, summary statistics with the operating-envelope conclusion breakdown, the full sections and events tables with readable reason text, the Exclusion stack with per-rule condition summaries and their source references, the input data register, generation provenance (id, run time, parameters, input-fingerprint count) and the complete change log — everything needed to review or archive a plan without opening QGIS. Offered beside the CSV exports; opens in the browser after export on request. Pure-python formatting covered headless by `tests/test_burial_report.py`.

Double-clicking the profile pane primes the Plan Builder's add-event KP with the clicked KP, switches to that tab and centres the map there.
- **Burial Planner — plan outcome strip on the profile:** a thin colour strip pinned to the top of the profile pane now shows the resulting plan — burial green, skips red, Insufficient Information grey, matching the map symbology, with KP-range/conclusion tooltips — so the profile reads as a complete picture (exclusion shading answers *why*, the strip answers *what was decided*). ### Added

- **RPL import wizard — "Re-run detection" button and per-encoding auto-assignment:** the detection page's Structure panel gains a *Re-run detection* button that discards the current mapping (including an auto-applied saved profile) and re-detects everything fresh from the sheet contents, plus a visible one-line explanation of why the current coordinate encoding was chosen. ### Changed

- **One slope convention across the plugin (review + consolidation):** every tool now reports along-route slope with the same sign — **positive = shoaling with increasing KP/chainage** (up-slope, the terrestrial elevation convention), side slope **positive = deeper to starboard** (the vehicle leans to starboard) — and the seabed datum (positive-down depths vs negative elevations) is auto-detected per profile, so the sign no longer silently flips between an MBES raster stored as depths and one stored as elevations. Documented in README "Slope methodology". Per tool:
  - *KP Mouse live profile*: slope was previously the raw `Δvalue/Δdistance` of whatever the source stored — the opposite sign for positive-down rasters vs elevation rasters, and inconsistent with the other tools — and undocumented. Now datum-normalised (+ve = up-slope, axis labelled), the fabricated 0° first station is gone, and coincident duplicate contour crossings from major+minor layers no longer punch `None` gaps or near-vertical spikes into the slope trace.
  - *Depth Profile tool*: the default sign (+ve = up-slope) is unchanged in meaning but is now datum-normalised before the *Invert Slope Sign* option is applied; the option now means +ve = deepening when checked and starts unchecked (its saved state moved to a new settings key because the checkbox's meaning changed). Side slope is likewise datum-normalised (+ve = deeper to starboard). The first station and non-advancing stations report no slope instead of a fabricated 0°. Side slope is computed before the single slope pass instead of triggering a full recompute of every segment metric (profiles with side slope enabled generate noticeably faster), and stale side-slope columns are cleared when the option is off.
  - *KP Range Depth + Slope Summary*: same sign as before (+ve = up-slope) but now datum-normalised per feature instead of assuming positive-down depths; directional extremes are renamed to self-documenting positive magnitudes (`slope_down_max_deg` / `slope_up_max_deg` / `side_stbd_max_deg` / `side_port_max_deg` — previously `slope_up_max_deg`/`slope_down_min_deg`/`side_port_min_deg` as signed values). Station placement now precomputes each part's cumulative segment lengths once and bisects, instead of re-measuring the whole part geodesically for every station (O(stations × vertices) → O(vertices + stations log vertices)); the *Interpolate between contour hits* parameter, which had no effect (both branches returned the same profile), is labelled as always-on for saved-model compatibility.
  - *Workbench / Burial Planner rules*: the signed slope series flips from its previous internal +ve = deepening to the plugin-wide +ve = up-slope (down/up-slope **limits are unaffected** — they are entered as magnitudes per direction and are remapped onto the new sign internally; direction-aware B→A limit swapping is unchanged). The unsigned and signed series are one implementation (unsigned = magnitude of signed), and the central-difference window is now **distance-based** — depths interpolated at kp ± the analysis step — instead of ±1 station index, so route-vertex and contour-crossing stations injected between the regular marks no longer shrink the window (which could turn a contour step into a near-vertical spike) and the coarse series measures slope at exactly the scale the 1 m boundary-refinement predicate re-measures (the predicate window is also clamped to the route rather than the scope, matching the one-step station margin). Assessment threshold rules reuse one sampled depth series per run instead of rebuilding the depth service and re-walking the route for every rule.
  - *Burial Planner profile crosshair*: the slope readout follows the new sign and is measured over ± the plan's analysis step (central difference on the displayed series) instead of one display-resolution interval (~5 m on a 15 km scope), so the number under the cursor matches what the slope rules evaluated.
- **Route KP lookups are chainage-indexed — full-detail profiles on 1000 km routes:** `RouteFrame.point_at_kp` re-walked every route vertex with one geodesic measurement per segment on *every* call, making dense sampling of long routes quadratic (stations × vertices) — the reason profile resolution had to be capped. The frame now builds a per-segment chainage index once (lazily, same segments and the same `measureLine` calls in the same order, so results are bit-identical — asserted by an equivalence check in `tests/test_burial_task.py`) and serves each lookup by bisection. Every consumer speeds up: plan-profile sampling, cross-offset sampling (3 lookups per station), threshold-rule station building (`RouteSampler.from_route` was one full-route walk *per station*), boundary-refinement predicates, event position stamping, and map hover/goto sync. The plan profile's station step now **follows the data**: a *Profile step* parameter (Exclusions row) defaults to Auto, which reads the smallest configured bathymetry raster cell size — sampling finer than the cell only re-reads the same cells — falling back to 5 m for contour-only sources, clamped between 2 m and the analysis step (so Generate can always reuse the stored samples) with a ~500k-station ceiling; a manual value overrides Auto and a changed target step marks the stored profile stale. Slope series over large profiles are memoised per (window, direction) so refreshes never recompute them.
- **Burial Planner — the Generate progress bar moves through the long phases:** analysis progress previously advanced only per completed rule, so the dominant phases — contour preparation and bathymetry sampling — sat at 0% with only a text message. Bathymetry preparation now reports 0–8%, station building 10%, and each rule's slot advances *during* its sampling (cancellation checks already ran throughout; all sampling stays on the background task, and a status line now also marks the brief main-thread "Applying generation results…" phase).
- **Burial Planner — change-log entries store row deltas, and the log appends without rewriting:** every edit previously snapshotted the *complete* events + sections tables into its before/after JSON and rewrote the whole `bp_change_log` table to add one row, so editing cost (and file size) grew with plan size × history length. Entries now keep only the added/removed/modified rows (`change_log.delta_tables` — rollback inversion is per-row keyed, so restore behaviour is unchanged), new entries are appended through the provider instead of a whole-table rewrite (with the old rewrite as fallback), and the next log seq is cached per plan instead of re-reading every entry's JSON payload per append. Covered by a new delta check in `tests/test_burial_io.py` and the existing rollback/undo checks in `tests/test_burial_store.py`.
- **Burial Planner — profile pane usability (alignment, crosshair, toggles, sizing, export):** the depth and slope plots now share one fixed left-axis width, so the x-linked KP axes align exactly (previously differing tick-label widths offset the two plot areas); the crosshair is mirrored onto the slope panel and hovering/clicking the slope panel drives the same crosshair, readout and map sync as the depth plot, with cross/absolute slope values added to the readout when the panel shows them; the longitudinal/cross/absolute series each get a coloured show/hide checkbox (persisted, replacing the in-plot legend); the split between the depth and slope panels is a draggable splitter with its position remembered, the dock's tabs-vs-profile split is likewise remembered and the profile pane holds a minimum height instead of being squashed by the tabs; the KP axis no longer relabels to "KP (kkm)" past KP 1000 (pyqtgraph SI auto-prefix disabled — depths likewise stay in metres); the standard pyqtgraph right-click menu (view-all, axis options, CSV/image export) is enabled on both plots, with plot clicks-to-map now left-button only so the menu doesn't fight the map sync; and the y-axis auto-scales to the data visible in the current KP window while panning/zooming. Display-only — stored plan profiles and samples are untouched. Covered in `tests/test_burial_task.py`.
- **Burial Planner — profile depth curve uses peak-preserving decimation:** long profiles were thinned by a naive stride for display, which could drop exactly the narrow bathymetric spike a burial engineer needs to see; the curve now hands pyqtgraph the full series with auto peak downsampling and clip-to-view.
- **Burial Planner — private cross-package calls promoted to public API:** the acquisition pipeline called nine underscore-prefixed helpers in `workbench/rules_inputs.py` / `rules_engine.py`; these now have stable public names (`resolve_layer`, `load_features_wgs84`, `search_rect`, `distance_to_geom_m`, `filter_expression`, `feature_buffer_m`, `acquire_manual`, `scope_intervals`, `cond_bounds`) documented as the Burial Planner's contract, so refactoring the workbench internals can no longer silently break burial.
- **Burial Planner — per-feature buffer refinement no longer rescans every feature per bisection step:** the widest `buffer_field` value (which bounds the candidate search rect) is computed once when the refinement predicate is built instead of on every evaluation.
- **Burial Planner — slope rules can evaluate over the vehicle footprint:** slope threshold rules gain a *Slope evaluation length* (m). Set it to the plough/trencher bearing length and the rule differences depth across that footprint — the gradient the machine actually spans — instead of the raw analysis-step window, which suppresses fine-scale terrain shorter than the vehicle. Unset (Auto) keeps the previous 2 × analysis-step window. The length is part of the rule config, so the acquisition cache invalidates when it changes and the 1 m boundary-refinement predicate evaluates over the same footprint.

### Fixed

- **Burial Planner — cross-offset sampling over contour bathymetry no longer stalls on long routes (and no longer invents depths):** the profile task's cross-offset phase ("Sampling cross-offset depths…", 75–100%) sampled each station's ± offset points by a nearest-contour scan — `closestPoint` plus a geodesic distance against every candidate contour, per station, per side — which is O(stations × contours) and appeared frozen (~hours) on a ~1000 km scope; on flat stretches the nearest contour could also be kilometres away, silently fabricating a cross depth. Cross-offset depths now use the same methodology as the along-route profile: the port/starboard offset polylines are intersected with the contours through the spatial index (chunked, so contour-free stretches cost one index query) and depths are interpolated between bracketing crossings only — stations with no bracketing crossings report no data instead of a value from a distant contour, and rasters keep fast point sampling at the offset positions. A 1000 km route with 1,500 contour lines and ~100k stations now completes the whole profile pass (along + both sides) in seconds. Stored plan profiles are unaffected (no schema change); contour cross-offset values refresh to the crossing-based figures on the next resample. Regression-tested in `tests/test_burial_task.py` (tilted-contour port/starboard split, no data outside the crossing range).
- **Burial Planner — a failure while applying analysis results is no longer silent:** the `QgsTask` completion guard ("never crash QGIS from a callback") also swallowed any exception raised while generation results were being applied and saved, so a store-write failure made *Generate* appear to do nothing. Failures now surface in the Plan Builder status and a warning dialog, and the full traceback is written to the QGIS message log (Burial Planner tab); the profile-sampling task's completion path logs likewise.
- **Burial Planner — editing an event's notes was audit-logged as `move_event`:** notes edits now record a dedicated `edit_event` action (undoable in the Plan Builder like other event edits) through a proper `PlanModel.set_event_notes` API instead of reaching into the model's private write path.

- **RPL import — split degrees/minutes/hemisphere coordinates now detected reliably (and preferred):** on real industry RPLs the wizard could fall back to "signed decimal degrees" pointed at the wrong sub-columns of a grouped "Latitude"/"Longitude" header, producing hundreds of warnings. Root cause: coordinate-column statistics were computed over every data-like row in the sheet, so one stray footer number ("Total route length … 1234.5 km") or banner value pushed a degrees column outside its plausible range and vetoed the otherwise clear deg/min/hemisphere triple. Detection now restricts statistics to the dominant contiguous body run, tolerates isolated outliers (at most 10%, always at least one) in the range and integer-degrees checks, and recognises hemisphere-first column order (`N | 50 | 12.5'`) alongside the usual `50 | 12.5' | N`. Split DDM remains the first-preference encoding whenever the triples exist. The decimal-degrees fallback now scores candidates instead of taking the first header match: columns that sit inside a deg/min/hemisphere group are never decimal degrees, derived trigonometry columns (radians/sin/cos) are penalised, and genuine fractional "Decimal Latitude (degrees)" columns win. Covered by three new fixtures in `tests/test_rpl_import_core.py` (footer contamination, hemisphere-first order, decimal fallback preference).
- **Workbench — closing or switching projects could delete RPLs from the workbench GeoPackage:** the dock's layer-registry sync (remove a workbench layer from the project → its registry entry is deleted) also fired when QGIS removed *every* layer while closing a project or opening another one with the dock open, silently deleting the registered RPLs (with their fits and assessments) from the store. Project teardown is now detected — via the project's `aboutToBeCleared`/`cleared` signals where available, plus an all-layers-removed heuristic on older builds — and never touches the registry. Issued (read-only) RPL revisions are additionally never registry-deleted by removing their layers from the project; the layers stay in the GeoPackage and can be re-added.
- **Workbench — duplicate layers from path-comparison misses:** finding an RPL's layers in the project compared GeoPackage paths by raw substring, which fails on Windows drive-letter case or slash differences (e.g. after a project save normalises the source path) and then loaded a second copy of the layer. All workbench layer lookup now goes through one normalised-path comparison (`workbench/project_layers.py`), shared by the RPL Manager, assessment panel, import wizard, and the dock's removal sync.
- **Workbench — dock now detaches its project-signal connections on plugin unload** (`WorkbenchDock.shutdown()`), and refreshes its tree when a different project is opened instead of showing the previous project's entities.

- **Workbench — guided "Import RPL…" wizard:** one action in the RPL Manager now takes an RPL workbook (.xlsx/.xlsm) or CSV all the way to a registered Workbench revision — no sheet names typed, no row counting, no Excel column letters, no separate *Register RPL* step. Page 1 scans every worksheet in the background and preselects the one with the most parsed positions; page 2 shows the actual worksheet in a virtual table with header/point/segment/range highlighting and lets you correct the layout (alternating point/segment rows *or* one-position-per-row, with explicit arriving/departing span semantics), data range, coordinate encoding (split degrees/minutes/hemisphere, combined DDM text, signed decimal degrees, or projected easting/northing transformed through an explicitly chosen CRS), units (km/m/nm distances, m/ft depths, percent-or-ratio slack, converted once and recorded), and the full column mapping — every detected assignment shows *why* it was chosen, unassigned columns are preserved as extra attributes by default, and mappings can be saved as named profiles keyed by a stable header signature for the next workbook with the same layout. Page 3 shows counts, stated KP range, stated route/cable length against the QGIS ellipsoidal computed length, and all diagnostics grouped by severity with double-click navigation back to the source row, plus a temporary route preview on the map with suspect positions marked (removed when the wizard closes). ### Fixed

- **Import MDB: a source `Depth` column silently discarded every feature in the table.** GeoPackage (SQLite) column names are case-insensitive, so a source attribute named `Depth` collided with the derived `depth` attribute, `CREATE TABLE` failed with `duplicate column name: depth`, and the layer was written with *zero* of its features — typically the contact/sample tables (`Sonar_Contact`, `Seismic_Contact`, `Mag_Contact_ID`, `CPT`, `Wreck`). Output field names are now de-duplicated case-insensitively: source attributes keep their names, later collisions are suffixed (`depth` → `depth_2`), and the renames are listed in the log. The same pass still renames `fid`, which is the GeoPackage primary key.
- **Import MDB: point and multi-part feature classes imported as nothing ("worker produced no output file"):** the GeoMedia geometry BLOB reader assumed one layout — a 16-byte header followed by an `int32` vertex count — which is only true for polyline and polygon primitives. Point and oriented-point BLOBs store three bare doubles with *no* count, so the reader interpreted the low mantissa word of X as a vertex count, rejected every row, and the table silently produced zero features; boundary (polygon-with-holes) and collection BLOBs failed the same way. A new decoder (`processing/geomedia_blob.py`) dispatches on the BLOB's own type byte and handles point, oriented point, polyline, polygon, boundary and collection/multi-line/multi-polygon variants, including nested sub-geometries. Metadata-led classification is unchanged for simple single-ring shapes, so existing line and polygon imports produce exactly the same layers as before. A second defect made the failure unreadable: an empty `outputs` dict is falsy, so the algorithm fell through to the non-split code path and reported a missing file instead of the real cause.
- **Import MDB: every attempted table now reports what happened.** The worker always returns a structured result (`status`, `row_count`, `non_null_geometry_count`, `blob_decoded_count`, `xy_fallback_count`, `invalid_geometry_count`, `geometry_types_found`, `outputs`, `message`), so the log distinguishes a genuinely empty table (`Subcropping_ROCK: rows=0; table is empty`, informational) from a populated table that yielded no geometry (`Mag_Contact_ID: rows=17, non-null BLOBs=17, BLOB decoded=0, XY fallback=17, outputs=Point`), which is escalated as an error. A failure while reading one table no longer aborts the rest of the database. Diagnostics are sanitised: file paths and long literals are stripped, and no record values, coordinates or BLOB contents are ever logged.

### Added

- **Import MDB — secondary geometry columns:** `GFeatures.PrimaryGeometryFieldName` names only the *primary* geometry column, but GeoMedia tables frequently carry a second one (typically `CoordGeocodePoint`) holding the geometry for rows whose primary BLOB is null. When the primary BLOB is null or undecodable, the remaining GeoMedia geometry columns are now tried before any coordinate fallback. Only genuinely decoded geometry is used — nothing is invented — recovered features are tagged `geometry_source = secondary_blob`, and the log reports the count and which columns were used. Because output is split by geometry type, existing layers are unchanged; recovered geometry appears as its own layer.
- **Import MDB — conservative coordinate-pair fallback for point data:** when a row's geometry BLOB is null or cannot be decoded, and the table has an explicitly recognised coordinate pair (Easting/Northing, East/North, X/Y, X_Coord/Y_Coord, Longitude/Latitude, Long|Lon|Lng/Lat — matched case-insensitively), a point is built from those columns. Values must be finite numbers; null, blank, non-numeric, NaN and infinite values are rejected, families are never mixed (an Easting is never paired with a Latitude), and a Depth column is never used as a horizontal ordinate. An explicit vertical field (Depth, Z, Elevation, …) produces a PointZ. Nothing is silent: every feature carries a new `geometry_source` attribute (`blob` or `xy_fallback`) and the log reports BLOB-decoded and fallback counts separately.
- **Import MDB — optional schema-aware table discovery** (`SUBSEA_MDB_SCHEMA_DISCOVERY=1`): `GFeatures` remains the authoritative source and the only thing read by default, so normal imports are as fast as before. When enabled, a secondary pass inspects the physical tables (names, columns and definition row counts only — no record data is read) and additionally offers tables with strong spatial evidence that were never registered. GeoMedia/Access metadata tables are excluded, and companion `*_Name`/`*_Text`/annotation tables and non-spatial lookup tables such as `Sediment_Classification` are reported with their row count and reason rather than being loaded or given invented geometry. The pass costs one table-definition parse per unregistered table, so it is off by default and capped by `SUBSEA_MDB_SCHEMA_BUDGET` (default 30 s).
- **Import MDB — polygons with holes and multi-part geometries** are decoded and, like MultiPoint, loaded when `SUBSEA_MDB_LOAD_ALL_GEOMS=1` is set.

### Changed

- **Import MDB — CRS parameter wording:** the parameter is now labelled *Source CRS / CRS of coordinates in MDB* and the log states that the CRS is assigned, not transformed — it has only ever assigned the source CRS. The stored parameter key is unchanged, so existing models and scripts keep working.

 Qt's built-in drag auto-scroll only engages in a thin 16 px band and only advances while the mouse is actually moving, so with a long task list there was no way to scroll to a drop target that wasn't in view while holding the drag. The task table now runs its own timer-driven edge auto-scroll: while a drag hovers within ~36 px of the top or bottom of the list it scrolls continuously — faster the closer the cursor is to the edge — with no mouse movement needed, stopping the moment the cursor moves back toward the middle, the drop lands, or the drag leaves the table. Works for single tasks and whole selected groups alike.
- **Reports window: Progress S-curve crashed with `TypeError: %c requires int or char`:** the Y-axis caption "Cumulative % complete (…)" was built with %-formatting, and the literal "% c" in the text parsed as a `%c` conversion. The literal percent sign is now escaped (`%%`).
- **Planner: a newly linked route stayed pinned at "(end)":** a task added after a route task deliberately inherits that route's reference positioned at its end ("follow-on work starts where the last task finished") — but the `line_end` pin survived linking a *different* feature, so e.g. a second vessel's freshly drawn transit line rendered as a point at its end instead of being traversed. Linking a task to a different feature now resets the location mode to "use the feature" (explicitly shared start/end/chainage positions still ride along unchanged), and a line task whose speed was blanked by that same inheritance is re-seeded with its resource's default speed so the transit immediately computes a duration.
- **`QgsMapLayerComboBox.setFilters() is deprecated` warning on QGIS ≥ 3.34** (planner Link-task dialog and workbench rule editors): the compatibility shim resolved the filter *enum members* from `Qgis.LayerFilter`, but OR-ing them could degrade to a plain int, which sip matched to the deprecated `QgsMapLayerProxyModel.Filters` overload. A new `layer_filters()` helper wraps the combined value in the `Qgis.LayerFilters` flags type (falling back for older QGIS 3 / QGIS 4 enum flavours), so the non-deprecated overload is always selected; all four `setFilters` call sites now use it.
- **KP Mouse Tool: `AttributeError: 'NoneType' object has no attribute 'stop'` spammed on every mouse move** (seen while moving a point feature with the Planner open): `cleanup_resources()` tears the tooltip timers down, but the canvas can keep delivering move events to the tool afterwards (e.g. when the tool is restored as the active map tool after an edit session), so `canvasMoveEvent` crashed on the dead timer every event. The tool now recreates its timers on demand in `canvasMoveEvent` and guards every other timer access (`canvasLeaveEvent`, `deactivate`, the persistent-tooltip chain), so a cleaned-up tool keeps working instead of flooding the log.
- **Planner GeoPackage still landing in `C:\WINDOWS\system32` on some machines:** the writable-folder probe used `os.access`, which is unreliable against Windows ACLs, and the last-resort fallback was the process working directory — which for QGIS launched from a shortcut *is* `system32`, recreating the exact failure the fallback was meant to avoid. - **BU Lowering Tool: trunk drawn disjointed from the BU, and a kink/dogleg below the sheave:** the cable-over-sheave rendering blended the arc-exit offset over a fixed 30 m of cable. When the deployed trunk was shorter than the blend (the whole early lowering, when only the ~15 m tail is out) the taper outlived the cable and dragged the trunk's bottom node ~2 m off the branching unit — the trunk and legs appeared as unconnected sections. And on longer trunks, concentrating the offset into a 30 m stretch bent the (otherwise dead-straight, taut) trunk into a visible S-shaped dogleg with a ~70 m curvature radius 5–35 m below the sheave — the "kink in the trunk catenary". The offset is now absorbed as a *linear-in-arc-length* taper spanning the whole suspended run down to the touchdown (or the far end): an affine shear that tilts the span rigidly about its pinned end, adds zero curvature anywhere, and always terminates the cable exactly on its solved attachment. Regression tests cover the pinned far end, the arc-exit tangency, and curvature transparency.
- **Quick model: cable laid on the seabed decayed to 0 kN:** bed tension was recomputed every step as pure friction decay from the *current* touchdown tension (`max(0, H − μws)`), so any bed run longer than `H/(μw)` — a few tens of metres — read 0 kN regardless of the tension it was actually laid with, and after the BU landed the legs' whole laid length went to zero. The frozen-lay model now records the converged bottom tension into each point as it is laid (the as-laid residual friction locks in); displayed bed tension keeps that as-laid value and only a slip zone next to the touchdown adjusts toward the current bottom tension, inside the Coulomb cone `H ± μws`. Pre-laid cable (the legs at the start of the lowering) is initialised with the residual of its first equilibrium.
- **Quick model: everything jumped/shifted on the seabed when the BU landed:** the frozen-lay span was rendered as a *forced tangent* catenary whenever the touchdown walk settled inside its band — and tangent `H = w·a` diverges as the hang height goes to zero at fixed layback (a flat span cannot hold surplus length). In the landing frames that injected phantom horizontal pulls (tens to hundreds of kN) into the BU force balance, spiked the touchdown tensions, and snapped the geometry between solution branches: legs collapsed from ~3.7 kN to 0.3 kN and re-rendered wholesale in one frame. The suspended span is now *always* the two-point catenary carrying the actual free length — identical to the tangent solution when the walk has settled, gracefully slack (or taut) off tangency, and bounded all the way to a hang point on the bed — so tensions and geometry are continuous through touchdown (legs now walk 2.5 → 3.7 → 4.8 → 5.2 kN across landing and freeze). The walk also peels laid cable when the free length cannot span the straight chord to the touchdown (an over-taut span would lift laid cable regardless of friction).
- **Quick model: single-frame tension blips and a silent "always converged" flag:** the BU force-balance Newton solve could stall on the stiff taut-trunk states (the taut-line penalty spring was ~2×10⁶ N/m, putting equilibrium inside a ~3 cm band probed with 5 cm finite-difference steps), leaving one-frame trunk-tension excursions of ±20–40 kN — while every snapshot claimed `converged=True`. The taut stiffness is now 2×10³ per unit weight (~15 cm stretch at 60 kN, about the elastic stretch of real cable), the FD step is 2 cm with a larger iteration budget (runs are net *faster* because Newton actually converges), and the snapshot carries the true residual: frames whose BU balance did not close within 1 % of the load scale are flagged non-converged with a warning instead of passing silently.
- **Depth Profile only plotted one raster when several were selected ([#6](https://github.com/k-mcmonagle/subsea-cable-tools/issues/6)):** ticking multiple rasters produced a single blended line, because sampling stopped at the first raster with valid data at each station and discarded the rest. Every selected raster is now sampled independently and drawn as its own labelled line, with gaps where a raster has no coverage, alongside the dashed composite series that slope and seabed length are still derived from. A new **Plot each raster** checkbox (raster mode only, remembered between sessions) turns the per-raster lines off for long routes where sampling every raster at every station is too slow; with a single raster selected the plot is unchanged. Switching back to contour mode no longer leaves stale raster lines on the depth plot, and rasters that do not cover the route are omitted from the legend. Derived outputs — slope, seabed 3D length, CSV and DXF export — are unaffected, still using the highest-resolution raster with valid data at each station.
- **QGIS 4 compatibility regressions in experimental tools:** Cable Lay Simulator table sizing, map overlays, and results-to-map fields; Explorer context menus and route filtering; and Workbench review dialogs, rule-layer filters, RPL map editing, assessment acquisition, and generated spatial layers now use the shared Qt5/Qt6 and QGIS 3/4 compatibility aliases. The static compatibility gate also covers polygon-layer filters and the additional aliases used by these tools.
- **Remaining unscoped Qt6 enums:** three unscoped PyQt6 enum accesses that raised `AttributeError` under QGIS 4 are now scoped/routed through the compatibility shim — `Qt.WindowContextHelpButtonHint` in the KP Mouse Tool "Go to KP…" dialog, `QSizePolicy.Ignored`/`Preferred` in the Cable Lay Simulator operation-scenario resize, and `QMessageBox.Yes` in the simulator's Reset-to-defaults prompt. The static compatibility gate now also flags unscoped `Qt.Window*Hint` flags. Confirmed against a live QGIS 4 / PyQt6 smoke run (dialog/widget construction, processing provider, planner suites).
- **Catenary Calculator V2 touchdown consistency on undulating seabed profiles:** on a wavy profile the touchdown-point (TDP) fixed-point iteration could report "converged" while leaving the stored geometry out of tolerance. The Picard step-size test bounds the *input* inconsistency, but the solver then locks in the *output* layback and re-solves there; on a non-contractive profile (|g′| > 1) that left a residual of roughly |g′|·tol (e.g. ~1.8 m at a 0.5 m step), so the depth sampled under the cable came from the wrong world-x. The solver now verifies the actual `|layback − TDP_x|` residual after locking in and escalates to the robust bracketed bisection (which solves `layback(x) = x` directly and returns its smallest-residual iterate) whenever Picard leaves the fixed point out of tolerance.
- **Planner/workbench GeoPackage in an unwritable folder:** with an unsaved QGIS project the default GeoPackage path was built from the process working directory, which for QGIS started from a Windows shortcut is `C:\WINDOWS\system32` — so opening the Planner failed with "Could not open or migrate the planner GeoPackage" and creating a scenario raised an unhandled `RuntimeError`. Unsaved projects now default to a writable folder in the active QGIS profile (falling back to the user home), the remembered project path is only stored once it has been written successfully, a remembered path that no longer resolves falls back to the default (only when no file exists there to lose), and scenario create/rename/duplicate/delete/anchor edits report a writable-location message instead of raising out of a Qt slot.
- **Planner transport bar jitter:** the playback status text (task, timestamp, percentage) resized itself as it changed, pushing the timeline slider around. The slider and status now share leftover width by fixed stretch factors and the status label elides long text (full text in its tooltip), so the bar keeps its layout at any window size on both Qt5 (QGIS 3) and Qt6 (QGIS 4). ## [1.5.1] - 2026-06-19

Maintenance and consistency release focused on distance/KP measurement and CRS handling, plus substantial enhancements to Catenary Calculator V2 (sloped / profiled seabed support, convergence and seabed-penetration reporting, and distributed buoyancy). Existing KP/measurement workflows are unchanged when defaults are kept; the one intentional behaviour change is that Catenary V2's *Bottom Tension* input is now the actual tension at the touchdown (`T_TDP`) rather than the horizontal force component (`H`) — identical on a flat seabed.

### Added
- **Catenary Calculator V2 — automatic multi-span seabed drape (standard model on profiled seabeds).** A second, independent static solver (`catenary/drape_solver.py`: lumped-node dynamic relaxation with kinetic damping, tension-only axial springs driven to the inextensible limit by rest-length correction, penalty seabed contact, Coulomb stick-slip friction, optional discrete bending stiffness) resolves the **full drape of the cable over the seabed profile**, including resting on high spots the single-span model can only flag as penetration, free spans bridging depressions, an anchored or free bottom end, and seabed friction. In **Profile seabed mode the drape runs automatically as part of every solve** and the drape-resolved geometry is what is plotted, hovered and exported (clamped onto the bed so the displayed cable never penetrates the seabed); the raw single-span curve through a high spot is no longer shown. The drape's boundary-condition inputs live in **Geometry** (Seabed end condition, On-bed length beyond TDP) and are only shown in Profile mode. Each free span and the hang from the ship (extent, length, max clearance, min bend radius, max tension) plus top/end tensions and contact status are reported in a table in the **Results** pane. Flat/Sloped modes keep the exact tangential single-span solution (a drape adds nothing there) and report the equivalent single-hang row. Validated against closed-form catenary results (top tension within 1 %, touchdown within 2.5 %, frictionless flat bed transfers H to the anchor within 2 %) in `tests/test_drape_solver.py`, and end-to-end through the dialog in `tests/test_catenary_v2_dialog.py`. Friction equilibria are lay-history dependent and reported as indicative. See `catenary/MODEL_NOTES.md`.

Round-trips through the assembly JSON (`friction_mu`).
- **Catenary Calculator V2 — per-segment bending stiffness (EI) and minimum-bend-radius (MBR) check.** New Solve Mode defaults plus Assembly segment columns for *EI* (kN·m²) and *MBR* (m); blank segment values inherit the Solve Mode defaults, and MBR `0` disables the check for that segment. EI is modelled in the drape solver as energy-consistent discrete three-node moments (`M = EI·κ`, lumped-mass curvature `κ = 2θ/(L1+L2)`), now using a compliance-weighted joint EI where adjacent assembly segments differ. The MBR check maps every modelled bend back to the local assembly segment, checks chute contact segment-by-segment, and uses adjacent-segment EI/MBR for point-load body kink estimates (`R ≈ √(EI·T)/P`), raising a red integrity banner when a local limit is violated.

- **Catenary Calculator V2 — buoyant assembly segments.** A negative segment weight is now honoured as distributed buoyancy (bows the cable upward), matching negative point loads and legacy distributed components. Previously any non-positive assembly-segment weight was silently replaced by the fallback cable weight, so buoyant segments had no effect. Blank/zero still means "use fallback weight" (back-compatible, warned); a new advisory flags net-buoyant segments and non-physical negative *in-air* weights.
- **Catenary Calculator V2 — surface-piercing detection and redundant-buoyancy estimate.** When a buoyant bight rises above sea level anywhere other than the final run up to the chute, the solver flags it, reports the affected arc length, the max height and an estimated **redundant (excess) buoyancy in kN**, and the plot clamps the displayed cable (and any bodies) to the surface over the region with a distinct orange marker — physically that section would float at the surface, not arc through the air. Tensions/geometry in flagged regions are explicitly marked non-physical.
- **Catenary Calculator V2 — convergence reporting and seabed-penetration detection.** The solver now judges convergence directly from the boundary-height and input residuals (tolerances scale with the integration step) and records a `converged` flag plus per-residual OK flags, instead of silently plotting a best-effort (possibly disconnected) curve. The dialog surfaces non-convergence with a red banner in the results pane and a colour-coded row in the solver-diagnostics view. Free-span **seabed clearance** is now computed for every solve; on a profiled seabed where the self-consistent single-span cable would pass through a high spot between the touchdown and the chute, the penetration is detected and clearly flagged (banner + red markers on the plot showing where the cable lies below the bed) while the geometry is kept self-consistent (the touchdown stays registered with the chute boundary condition rather than being relocated, which a single-span static model cannot do physically). - **Catenary Calculator V2 — sloped / profiled seabed support.** The solver previously assumed a flat horizontal seabed at the chute-depth elevation; it now accepts a seabed *profile* and applies the correct touchdown-point (TDP) boundary condition `V(0) = H · tan(α_TDP)`, so the cable departs the bed tangent to the local seabed slope. Three modes are exposed in the V2 dialog:
  - **Flat** (default, bit-for-bit identical to previous behaviour).
  - **Sloped** — single global planar slope, depth taken at the chute as the reference. Positive slope = bed deepens away from chute.
  - **Profile** — arbitrary (distance-from-chute, depth) polyline; depth is linearly interpolated and slope is taken from an adaptive centred-difference of the polyline. Rows can be entered by hand, pasted from the clipboard, or loaded from a CSV/TSV file.

The solve uses an Aitken-Δ² accelerated fixed-point on the TDP horizontal position (typically ≤3 iterations) on top of the existing H-bisection; the flat case retains the single-solve fast path. A sliding-stability warning is emitted when `|tan α| > 0.2` (advisory) or `> 0.4` (severe). Per-solve diagnostics now include TDP iteration count, TDP world position, TDP depth, and TDP slope. Legacy callers passing only `water_depth_m` continue to work unchanged.

### Fixed
- **Catenary Calculator V2 — touchdown position could silently fail to converge on undulating seabed profiles.** The TDP fixed-point iteration (Picard + Aitken Δ²) is non-contractive on wavy bathymetry (|g′| > 1 when local slopes are steep); on failure it fell back to its *initial guess* with no warning. That guess came from `S_guess = water_depth + chute_height + 1` using the raw Water Depth spinbox, so e.g. a stale 1000 m spinbox over a 150 m-deep profile produced "TDP at 1011.00 m from chute" with a 253 m layback — an inconsistent world frame in which the automatic drape sampled the flat profile tail instead of the waves under the cable and the displayed cable cut straight through the seabed humps. Fixes: (1) the TDP seed and `water_depth_m` now use the seabed depth at the chute, not the spinbox; (2) Aitken extrapolations are clamped into the observed landscape; (3) on non-convergence the solver runs a **robust bracketed bisection** on `f(x) = layback(x) − x` (coarsened integration step for the scan, full resolution for the lock-in), selecting the *smallest* self-consistent touchdown — the first tangential touchdown coming from the chute; (4) every solve now records a **TDP self-consistency residual** (`layback − TDP x`) in diagnostics, and an inconsistent result is flagged non-converged with a red banner instead of rendering silently; (5) the auto-drape refuses to run in an inconsistent frame (reported in Results). Regression-tested at solver level (`test_undulating_profile_tdp_self_consistency_with_bad_seed`) and end-to-end through the dialog with the exact field configuration (`test_wavy_profile_with_stale_water_depth_stays_consistent`).
- **Catenary Calculator V2 — stale Water Depth spinbox no longer distorts Profile-mode rendering and checks.** Plot depth bounds now follow the sampled seabed (previously a 1000 m spinbox over a 150 m profile stretched the axis to 1000 m on a fresh view); TDP/plot label placement and DXF text sizing use the touchdown depth; the Catenary Length minimum-feasible-length check uses the shallowest profile depth instead of the spinbox (which could spuriously reject feasible lengths, or under-check); the DXF on-bed assembly extension follows the seabed profile instead of a flat line at the spinbox depth.
- **Ellipsoid `"NONE"` sentinel bypassed the WGS84 fallback (silent planar units).** `QgsProject.ellipsoid()` returns the literal string `"NONE"` (not an empty string) when the project ellipsoid is unset or set to "None / Planimetric". `make_distance_area` only treated the *empty* string as unset, so `setEllipsoid("NONE")` succeeded and every "ellipsoidal" measurement silently degraded to planar — **degrees reported as if they were kilometres** on geographic CRSes. The helper now treats `"NONE"`/empty as unset and falls back to WGS84 (as documented), and verifies the `setEllipsoid` return value. Planar measurement remains available via the explicit Cartesian mode.
- **Catenary Calculator V2 — spurious refinement deltas on sloped/profiled seabeds.** The half-step "refinement check" diagnostic re-integrated from a default TDP world-x of 0, sampling the seabed depth at the chute instead of at the converged touchdown. On a 10° slope a fully converged solve reported a bogus ~116 m position delta, wrongly suggesting severe discretisation error. The refined integration now seeds the converged TDP position.
- **Catenary Calculator V2 — failed solves no longer corrupt the Bottom Tension input.** In Bottom Tension mode on a sloped seabed the solver internally rescales the user's `T_TDP` to `H = T·cos α` inside `cfg`; if the solve raised (infeasible configuration), the scaled value was left behind and silently changed the next solve's input. The restore now runs in a `finally` block.
- **Catenary Calculator V2 — "Profile" seabed mode with an incomplete table no longer silently computes on a flat seabed.** Fewer than two valid profile rows now raises a clear error instead of falling back to Flat while the UI claims a profile is in use.
- **Catenary Calculator (Legacy V1) — "Catenary Length" mode failed for lengths > ~2.41× water depth.** The bisection upper bracket (`q·S`) sits below the true root whenever `S > (1+√2)·h`, so e.g. a 300 m cable in 100 m water raised "Function does not change sign over interval". Replaced with the exact closed form `H = q·(S² − h²)/(2h)` (from the identity `s² = h² + 2ah`).
- **Catenary Calculator (Legacy V1) — "Layback" mode failed for layback > ~14× water depth** (fixed upper bracket `q·h·100`), a realistic shallow-water case (e.g. 350 m layback in 20 m water). The bracket now starts from the flat-catenary estimate `a ≈ x²/(2h)` and expands until it spans the root.
- **Catenary Calculator (Legacy V1) — "Top Tension" mode** now uses the exact identity `H = T_top − q·h` and rejects physically unachievable inputs (`T_top ≤ q·h`) with a clear message instead of a cryptic bracketing error.
- **Calculate Seabed Length — "Output at Regular KP Intervals" mode crashed.** A duplicated fields/sink construction block created the output sink a second time *without* the `kp_start`/`kp_end`/segment fields, so writing interval rows failed. The duplicate block is removed.
- **Calculate Seabed Length — interval segments were straight chords, not the route.** `_extract_segment` joined the interval's endpoints with a straight line, under-reporting segment plan length and sampling bathymetry off-route on curved routes. It now uses the shared `extract_line_segment` linear-referencing primitive so segments follow the actual route.
- **Calculate Seabed Length — zero-coverage fallback now matches its warning.** With no bathymetry coverage the warning claimed "seabed length equals plan length" but the output was `0.0`; the output now falls back to the plan (2D) length as stated.
- **Import Excel RPL — DMS coordinate validation.** Latitude/longitude parsing now rejects minutes ≥ 60, latitude hemisphere letters other than N/S, longitude hemisphere letters other than E/W, and out-of-range results (>90°/>180°), routing those rows through the existing invalid-row warning instead of importing silent garbage (e.g. a transposed lat/lon column mapping was previously accepted).
- **QGIS smoke-test harness never initialised `QgsApplication`,** so the ellipsoid/CRS registry was empty and 9 of 20 distance/KP smoke checks failed identically on QGIS 3.40 and 4.0 regardless of plugin correctness (and, conversely, could not have caught the `"NONE"` regression above). The runner now boots a headless `QgsApplication` when run standalone.
- **RPL Route Comparison:** distance calculator now goes through `make_distance_area`. Previously it called `setEllipsoid(project.ellipsoid())` directly with no fallback, so an unset project ellipsoid silently disabled ellipsoidal mode and produced planar/degree distances on geographic CRSes.

- **Plugin entry points:** removed an unused `run()` method on the main plugin class along with its dead `SubseaCableToolsDialog` import and `.ui` file (the dialog was never wired to any action and `run()` would have raised `AttributeError` if invoked).

- **KP Mouse Tool / cartesian mode:** previously, on QGIS ≥ 3.30 (where `setEllipsoidalMode()` is gone) selecting cartesian mode left the distance area in an undefined state. Building via the shared helper now correctly leaves the ellipsoid unset for planar measurements.
- **KP Mouse Tool — range ring alignment:** the dashed range ring rendered around the click origin now sits exactly on the cursor's reported geodesic range. The ring is built as a true geodesic circle on the spheroid (sampled with `QgsDistanceArea.computeSpheroidProject` and transformed back to the project CRS), instead of an Euclidean / flat-Earth approximation. Previously the ring drifted off the cursor whenever the project CRS had a non-unity scale factor at that location (e.g. Web Mercator at high latitudes) or used non-metre map units. The same fix applies to the saved "Place Range Ring" polygon feature.
